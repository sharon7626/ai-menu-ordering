# 店家模式與雙模式整合驗收紀錄

驗收日期：2026-08-07

## 驗收範圍

本次使用全新的暫存 SQLite 資料庫，依序驗證：

1. 上傳合法 PNG 菜單並取得結構化辨識結果。
2. 將人工確認資料建立為店家固定菜單。
3. 以固定公開網址讀取正確菜單，並取得只含公開網址的 QR Code。
4. 兩位顧客分別選餐、送單並取得不同個人訂單編號。
5. 顧客以私密個人連結查看自己的訂單。
6. 店家以私密管理連結依訂單編號與姓名查看兩位顧客的餐點。
7. 同一資料庫另外建立團購並送單，確認團購與店家訂單互不混淆。
8. 第一階段示範管理 API 不會讀到團購或店家顧客資料。
9. `data/menu.json` 在完整流程前後內容完全相同。

AI 辨識在此整合測試使用固定測試回應，不消耗 Gemini 免費額度；不需要真實 API Key，也不會產生外部費用。

## 雙模式隔離結果

- 店家訂單以 `store_profile_id` 歸屬，團購訂單以 `group_session_id` 歸屬，兩者不可同時存在於同一張訂單。
- 建立店家兩張訂單後再建立團購訂單，店家後台仍只有原本兩張店家訂單。
- 店家個人訂單編號以 `S-` 開頭；團購訂單編號使用團購公開代碼，編號不混用。
- 舊示範管理 API 只查詢沒有團購及店家關聯的示範訂單，不會洩漏顧客姓名。
- `data/menu.json` 仍只是示範與備援資料，店家與團購建立流程都不會覆寫它。

## 安全檢查

- 店家管理 Token 與顧客個人 Token 位於網址片段，後端 API 以 `Authorization` 標頭驗證。
- 資料庫只保存 Token 的 SHA-256 雜湊，公開菜單與店家管理回應都不含 Token 或雜湊。
- QR Code 只包含店家固定公開網址，不含查詢參數、網址片段或管理資訊。
- 顧客送出的資料只有品項識別碼與數量；名稱、單價、小計及總金額均由後端依菜單重新計算。
- 店家後台依店家關聯查詢，不會混入另一家店、團購或示範模式訂單。

## 使用者手動驗收方式

1. 在專案根目錄啟動後端：

   ```powershell
   C:\Users\sharo\anaconda3\python.exe -m uvicorn backend.main:app --reload
   ```

2. 開啟 `http://127.0.0.1:8000/upload`，上傳菜單並完成修正。
3. 選擇「建立店家固定菜單」，保存公開菜單連結與店家管理連結。
4. 用兩個不同分頁開啟公開菜單連結，各自選餐、輸入不同姓名並送單。
5. 各分頁點開自己的個人訂單連結，確認編號、姓名、餐點與總金額。
6. 開啟店家管理連結，確認後台能依兩個訂單編號與姓名分辨餐點。
7. QR Code 在本機會包含 `127.0.0.1`，適合確認圖案與網址；部署後才會自動包含正式公開網域，供手機掃描。

若 Gemini 免費額度暫時用完，上傳辨識步驟可能無法進行；這不影響不使用外部 API 的完整自動整合測試。
