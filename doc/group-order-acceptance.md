# 團購模式整合驗收紀錄

驗收日期：2026-08-07

## 驗收範圍

本次使用全新的暫存 SQLite 資料庫，依序驗證：

1. 上傳合法 PNG 菜單並取得結構化辨識結果。
2. 將人工確認資料建立為獨立團購菜單快照。
3. 以公開代碼讀取正確菜單。
4. 兩位參與者分別送出訂單並取得不同個人訂單編號。
5. 參與者使用私密個人連結查看自己的訂單。
6. 統籌使用私密管理連結查看所有個人明細及餐點彙整。
7. 統籌關閉團購並取得純文字摘要。
8. 團購關閉後拒絕新訂單。
9. 第一階段示範菜單點餐 API 仍可獨立送單。
10. 舊管理後台只顯示非團購示範訂單，不洩漏團購參與者資料。

AI 辨識在此整合測試使用固定的測試回應，不消耗 Gemini 額度；真實 Gemini 圖片辨識已在 Todo 第 17 項獨立驗收。

## 安全檢查

- 公開團購 API 不回傳管理 Token、管理 Token 雜湊或資料庫內部 ID。
- 個人訂單與管理 API 都必須以 `Authorization` 標頭提供正確私密 Token。
- 管理與個人 Token 位於瀏覽器網址片段，不會出現在伺服器請求網址。
- 資料庫只保存 Token 的 SHA-256 雜湊。
- 瀏覽器送出的價格不被採用，後端會依團購菜單快照重新核價。
- 舊的無權限示範管理後台已排除所有團購訂單，避免參與者姓名外洩。
- `data/menu.json` 在完整流程前後內容完全相同。

## 手動測試方式

1. 在專案根目錄執行：

   ```powershell
   C:\Users\sharo\anaconda3\python.exe -m uvicorn backend.main:app --reload
   ```

2. 統籌開啟 `http://127.0.0.1:8000/upload`，上傳一張菜單並確認內容。
3. 保存建立成功畫面中的團購代碼與統籌管理連結。
4. 使用另一個瀏覽器分頁開啟參與者連結，選餐、輸入姓名並送出。
5. 再用另一個分頁模擬第二位參與者送單。
6. 回到統籌管理連結，確認個人明細、餐點彙整及總金額。
7. 按下「關閉團購」，再回參與者頁嘗試送單，應顯示團購已截止。
8. 按下「複製摘要」，貼到記事本確認內容。
