# 菜單檔案上傳規格

## 1. 文件目的

本文件定義第二階段菜單上傳功能接受的檔案，以及驗證失敗時顯示給店家的訊息。先統一規則，能讓後續的上傳頁面與 FastAPI API 使用相同判斷，避免前端顯示可以上傳、後端卻拒絕的情況。

本規格只負責判斷檔案能否進入後續處理流程，不代表 AI 一定能正確辨識內容。

## 2. 允許的檔案

一次只能上傳一個菜單檔案。

| 菜單類型 | 允許的副檔名 | 預期內容類型（MIME type） | 頁數限制 |
| --- | --- | --- | --- |
| JPEG 圖片 | `.jpg`、`.jpeg` | `image/jpeg` | 不適用 |
| PNG 圖片 | `.png` | `image/png` | 不適用 |
| PDF 文件 | `.pdf` | `application/pdf` | 必須剛好一頁 |

副檔名判斷不分英文大小寫，例如 `.JPG` 與 `.jpg` 視為相同格式。

## 3. 驗證規則

檔案必須依下列順序通過檢查，通過後才能進入 AI 辨識流程：

1. 使用者已選擇一個檔案。
2. 一次只有一個檔案。
3. 檔案不是空檔案。
4. 副檔名是 `.jpg`、`.jpeg`、`.png` 或 `.pdf`。
5. 檔案實際內容與副檔名、MIME type 相符；不可只改副檔名冒充另一種格式。
6. 檔案可以正常讀取，沒有損壞。
7. PDF 必須剛好一頁；零頁或多頁 PDF 都不接受。
8. 單一檔案大小不得超過 `10 MB`（10 × 1024 × 1024 bytes）。

瀏覽器端可以先做基本檢查，提供較快的提示；FastAPI 後端仍必須重新執行相同檢查，不能只相信瀏覽器送來的檔案資訊。

## 4. 錯誤訊息

錯誤訊息需直接告訴使用者發生什麼事與如何處理，不顯示程式例外、伺服器路徑或其他內部資訊。

| 錯誤識別碼 | 發生情況 | 顯示給使用者的訊息 |
| --- | --- | --- |
| `FILE_REQUIRED` | 沒有選擇檔案 | 請選擇一個菜單檔案。 |
| `MULTIPLE_FILES_NOT_ALLOWED` | 一次選擇超過一個檔案 | 一次只能上傳一個菜單檔案。 |
| `EMPTY_FILE` | 檔案大小為 0 | 這個檔案是空的，請重新選擇菜單檔案。 |
| `UNSUPPORTED_FILE_TYPE` | 副檔名不在允許清單 | 檔案格式不支援，請上傳 JPG、PNG 或一頁式 PDF。 |
| `FILE_TYPE_MISMATCH` | 實際內容、MIME type 與副檔名不一致 | 檔案內容與副檔名不一致，請重新匯出後再上傳。 |
| `UNREADABLE_FILE` | 檔案損壞或無法解析 | 無法讀取這個檔案，請確認檔案沒有損壞後再試一次。 |
| `PDF_PAGE_COUNT_INVALID` | PDF 不是剛好一頁 | 目前只支援一頁式 PDF，請只保留一頁後再上傳。 |
| `FILE_TOO_LARGE` | 檔案超過 10 MB | 檔案超過 10 MB，請縮小檔案後再試一次。 |
| `UPLOAD_FAILED` | 非上述情況的暫時性上傳失敗 | 檔案上傳暫時失敗，請稍後再試一次。 |

若同一檔案同時有多個問題，依第 3 節的檢查順序回傳第一個問題，避免一次顯示太多訊息。

## 5. 可以進入後續流程的條件

只有符合以下所有條件的單一檔案，才能被視為上傳驗證成功：

- 格式為有效的 JPG、JPEG、PNG 或 PDF。
- 檔案內容與宣告格式一致且可讀取。
- PDF 剛好一頁。
- 檔案不是空檔案。
- 檔案大小未超過 10 MB。

驗證成功只代表可以進入 AI 辨識，不代表辨識結果已確認，也不得直接覆寫正式的 `data/menu.json`。

上傳頁選擇檔案後應先顯示預覽。JPG、PNG 可由使用者拖曳框選實際菜單範圍，再把裁切後的圖片送入 AI 辨識；可取消裁切或恢復使用完整圖片。一頁式 PDF 第一版只顯示整頁預覽，不提供瀏覽器內裁切。

## 6. 本階段不處理

- 不接受 GIF、BMP、TIFF、HEIC、Word、Excel 或其他未列出的格式。
- 不接受多頁 PDF。
- 不在本任務選擇或串接 AI API。
- 通過驗證的檔案目前不會永久保存，也不會直接覆寫正式菜單。
- 不保證模糊、傾斜、手寫或版面複雜的菜單能被正確辨識。
- 不提供圖片旋轉或一般圖片編輯；只提供辨識前的矩形範圍裁切。

## 7. 上傳頁面與 API

- 店家頁面：`GET /upload`
- 上傳 API：`POST /api/menu-uploads`
- 請求格式：`multipart/form-data`
- 檔案欄位名稱：`file`

成功時回傳 HTTP `200 OK`：

```json
{
  "success": true,
  "message": "檔案上傳成功，已通過基本驗證。",
  "file": {
    "name": "menu.pdf",
    "content_type": "application/pdf",
    "size": 431,
    "page_count": 1
  }
}
```

驗證失敗時，`detail` 會包含本文件第 4 節的錯誤識別碼與訊息。例如：

```json
{
  "detail": {
    "code": "PDF_PAGE_COUNT_INVALID",
    "message": "目前只支援一頁式 PDF，請只保留一頁後再上傳。"
  }
}
```
