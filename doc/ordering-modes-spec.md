# 點餐模式與資料歸屬規格

最後更新：2026-08-07

## 1. 文件目的

本文件說明團購模式與店家固定菜單模式如何共用既有的菜單、購物車與訂單功能，同時避免把所有菜單錯誤地存成全站唯一資料。

## 2. 共同核心

兩種模式共用以下能力：

- JPG、PNG、一頁式 PDF 上傳及 AI 辨識。
- 餐廳名稱、分類、品項名稱與價格的人工確認。
- 統一菜單資料格式。
- 點餐頁面、數量調整、購物車與總金額。
- 每個已選餐點的選填自由文字備註。
- 顧客姓名、個人訂單編號及訂單明細。
- 未登入訪客的聯絡方式、6 碼修改碼，以及同一身分加購或取代原訂單的流程。
- SQLite 訂單儲存及管理畫面。

## 3. 模式差異

| 項目 | 團購模式 | 店家固定菜單模式 |
| --- | --- | --- |
| 主要管理者 | 一般使用者中的統籌 | 店家 |
| 菜單來源 | 每次團購上傳任意店家菜單 | 店家預先設定自己的菜單 |
| 菜單生命週期 | 屬於單次團購的快照 | 長期保存，可由店家更新 |
| 顧客入口 | 團購代碼或分享連結 | 店家固定網址或 QR Code |
| 管理入口 | 不公開的統籌管理連結 | 不公開的店家管理入口 |
| 訂單接收者 | 統籌先彙整，再自行向店家訂購 | 店家直接從後台查看 |
| 主要輸出 | 以姓名顯示的個人明細、依餐點及備註分組的彙整、文字摘要、Excel 餐點彙整、訂購者合計與個人明細 | 依餐點及備註分組的彙整、個別顧客訂單、Excel 餐點彙整、顧客合計與顧客明細 |
| 人工確認能力 | 鎖定 AI 辨識的分類、品項與價格，只勾選本次提供品項；未辨識到餐廳名稱時可手動輸入 | 修改 AI 辨識結果，並可增刪固定菜單的分類與品項；未辨識到餐廳名稱時手動輸入 |
| 顧客備註 | 每個已選餐點可填選填自由文字備註 | 每個已選餐點可填選填自由文字備註 |

## 4. 編號與連結

### 4.1 團購代碼

- 短、容易輸入及分享。
- 只用來進入某次團購的公開點餐頁。
- 不得用來查看全部參與者資料或關閉團購。
- 代碼必須由後端產生並檢查沒有重複。

### 4.2 統籌管理連結

- 使用比團購代碼更長、不可猜測的隨機 Token。
- 只有持有連結的統籌可以查看全部個人訂單、彙整結果及關閉團購。
- Token 屬於機密管理資訊，不顯示在一般參與者頁面。
- 後端只在建立團購時回傳完整管理連結；資料庫應保存 Token 的雜湊值，不保存可直接使用的原始 Token。
- 完整 Token 不得寫入程式碼、Git、一般操作紀錄或錯誤訊息。

### 4.3 個人訂單編號

- 每次成功送單後產生。
- 同一次團購或店家訂單中不可重複。
- 與顧客姓名一起顯示，協助參與者、統籌或店家辨識餐點屬於誰。

### 4.4 店家固定網址與 QR Code

- 固定網址指向該店家目前供應的菜單。
- QR Code 只包含公開點餐網址，不得包含店家管理 Token。
- 第一版只有單一店家模式，但網址與資料結構仍應保留店家識別方式。

## 5. 菜單資料歸屬

### 5.1 示範菜單

`data/menu.json` 是開發、教學及未串接 AI 時的示範菜單。它繼續支援既有點餐底座，但不是未來兩種模式共同覆寫的正式資料位置。

### 5.2 團購菜單

- 屬於單一團購。
- 從統籌確認後的 AI 結果建立。
- 建立後保存為快照，避免其他團購或店家菜單更新時改變既有訂單。

### 5.3 店家固定菜單

- 屬於店家。
- 店家可重新上傳、確認並更新。
- 更新只影響之後顧客看到的菜單；既有訂單保留送單當下的品項名稱與價格。

## 6. 訂單顯示原則

每張個人訂單至少包含：

- 個人訂單編號。
- 顧客或參與者姓名。
- 品項名稱、單價、數量、小計與該餐點的選填備註。
- 個人總金額。
- 建立時間。
- 所屬團購或店家。

團購統籌應看到兩個角度：

1. 依參與者：誰點了哪些餐點、個人金額多少。
2. 依餐點及備註：每個品項在相同需求下總共幾份、合計多少；不同需求分列。

一般參與者只查看自己的訂單，不顯示其他參與者完整資料。

團購與店家固定菜單都採相同的訂單身分保護：同一 Google 帳號或同一正規化訪客聯絡方式，在相同團購或相同店家中只保留一張目前訂單。再次送單時可選擇加購或取代，且沿用原訂單編號。未登入訪客第一次送單須設定 6 碼修改碼；換裝置後以同一聯絡方式與正確修改碼載入原訂單。後端只保存修改碼雜湊，歷史未設定修改碼的訂單不自動補值。

## 7. 團購狀態

第一版只需要兩個狀態：

| 狀態 | 行為 |
| --- | --- |
| `open` | 參與者可以送出訂單。 |
| `closed` | 拒絕新訂單，統籌仍可查看及複製統計。 |

本階段不增加付款、店家接單、製作中、完成或取餐等複雜狀態。

## 8. 第一版輸出方式

團購完成後提供「複製純文字摘要」與「下載 Excel 表格」。文字讓統籌貼到通訊軟體或照著打電話；Excel 包含「餐點彙整」、「訂購者合計」與「個人明細」三張工作表。相同品項的不同備註需求必須相鄰排列，但仍各自統計數量與金額。「訂購者合計」每張送出的訂單各列一筆姓名、餐點總數量、合計金額與送單時間；即使姓名相同也不合併，以免不同人的同名訂單被誤算。

Excel 不包含管理 Token。列印版或 PDF 可以在團購主流程穩定後再增加；第一版不自動呼叫任何通訊平台或店家系統。

## 9. 開發順序決策

1. 先完成團購資料格式、團購代碼、參與者送單與統籌彙整。
2. 驗收完整團購流程。
3. 再以相同點餐核心增加店家固定菜單、固定網址、QR Code 與店家訂單後台。
4. 最後執行兩種模式的整合驗收及部署準備。

## 10. 發布前操作決策

- 首頁先讓使用者選擇團購或店家模式，避免把早期固定示範菜單誤認為正式首頁。
- 兩種模式都從相同的菜單上傳與 AI 辨識能力開始，但確認後保存到不同歸屬。
- 店家固定菜單需要長期維護，因此店家確認頁可增刪分類與品項。
- 團購是單次使用，不提供菜單品項增刪。
- 團購建立時鎖定 AI 辨識結果與價格，主揪只勾選這次開放點餐的品項；內容辨識錯誤時重新上傳清楚圖片。
- 菜單沒有印店名或 AI 無法辨識餐廳名稱時，團購主揪與店家都可以在確認階段手動輸入一個方便辨識的名稱；餐點名稱與價格仍遵守各模式原有規則。
- 團購與店家公開點餐頁將同品項 L／XL 顯示在同一列，各規格仍有自己的價格、數量及備註。
- 店家確認菜單時可新增或刪除分類與品項；這些控制不提供給團購主揪。
- 圖片上傳後先顯示預覽，JPG、PNG 可在辨識前框選菜單範圍；團購篩選結果會直接決定建立後提供給參與者的品項，不只是隱藏畫面列。
- 所有主要分頁最上方只放一個「首頁」按鈕；首頁本身保留三種角色入口，不顯示早期固定示範菜單連結。
- 兩種模式都允許為每個已選餐點填寫最多 200 字的自由文字備註，例如「小辣」或「半糖少冰」。
- 備註不改變 AI 辨識出的菜單單價；第一版不建立固定糖度、冰量、加料、尺寸或套餐選單，也不做自動加價。
