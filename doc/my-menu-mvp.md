# 我的菜單 MVP 評估

最後更新：2026-08-11

## 結論

可以在不重構既有團購快照與店家固定菜單的前提下完成。採用獨立的 `user_saved_menus`，只保存登入者已確認並建立過團購的標準菜單 JSON。

## 最小流程

1. 登入者確認菜單並建立團購。
2. 同一資料庫交易建立團購快照，並以內容指紋保存或更新本人常用菜單。
3. 使用者在「我的菜單」選擇一份菜單。
4. 系統建立新的團購代碼、管理 Token 與獨立快照，不重新呼叫 Gemini。

## 安全與資料邊界

- 只以後端驗證後的 `owner_user_id` 查詢與建立。
- 不回傳其他帳號菜單，也不接受前端指定 owner。
- 新團購仍有自己的快照；日後菜單變更不會改寫歷史團購。
- 不改店家固定菜單、歷史訂單、Excel、QR Code 或既有 Token。

## 本版不做

- 常用菜單的複雜版本管理、分享、協作或公開市場。
- 從歷史訪客團購猜測菜單擁有者。
- 直接編輯菜單；需要修改時仍走既有上傳與確認流程。
