# 我的菜單 MVP 評估

最後更新：2026-08-11

## 結論

「我的菜單」同時呈現兩種用途，但底層資料仍保持分離：

- 團購常用菜單使用 `user_saved_menus`，可再次建立新團購。
- 店家固定菜單使用既有 `store_profiles`／`store_menus`，以可為空的帳號擁有者關聯提供跨裝置管理。

## 最小流程

1. 登入者確認菜單並建立團購。
2. 同一資料庫交易建立團購快照，並以內容指紋保存或更新本人常用菜單。
3. 使用者在「我的菜單」選擇一份菜單。
4. 系統建立新的團購代碼、管理 Token 與獨立快照，不重新呼叫 Gemini。
5. 登入者建立店家固定菜單後，菜單以「店家固定菜單」標示在同一頁，並可進入調整菜單、店家訂單或公開點餐頁。

## 安全與資料邊界

- 只以後端驗證後的 `owner_user_id` 查詢與建立。
- 不回傳其他帳號菜單，也不接受前端指定 owner。
- 新團購仍有自己的快照；日後菜單變更不會改寫歷史團購。
- 店家固定菜單只能由後端驗證後的擁有者帳號或原 management Token 管理。
- 舊固定菜單只有持有原 management Token 的登入者可以認領，不依店名、公開網址或 QR Code 猜測擁有者。
- 不改歷史訂單、Excel、QR Code 或既有 Token。

## 本版不做

- 常用菜單的複雜版本管理、分享、協作或公開市場。
- 從歷史訪客團購猜測菜單擁有者。
- 團購常用菜單的直接欄位編輯；需要修改時仍走既有上傳與確認流程。
